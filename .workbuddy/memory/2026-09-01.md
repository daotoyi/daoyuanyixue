## APK v1.11.278 构建 + 下载页换自定义域名 (去掉 CloudBase 测试域名警告)
- **触发**: 用户下载 APP 时看到腾讯云「测试域名仅供开发测试」警告页, 且链接指向
  `/apk/daoyuan-v1.11.221.apk`(旧版本)。用户已启用自定义域名, 要求去掉该提示
- **APK 构建** (v1.11.278, 4.1MB, 包内 version.js 校验 = v1.11.278 ✅):
  - ⚠️ **`cap` 不在根目录**: capacitor CLI 装在 `mobile/node_modules/.bin/cap`,
    必须 `cd mobile && ./node_modules/.bin/cap sync android`, 直接 `npx cap` 会报
    "could not determine executable to run"
  - 流程: 更新下载页版本 → 重建 H5 → cap sync → `./gradlew assembleRelease --no-daemon` → 复制产物
- **⭐ 重大发现: 自定义域名 club.zhenhesheng.cn 的路径映射不统一**
  | 访问路径 | 实际读取 | 证据 |
  |---|---|---|
  | `club.zhenhesheng.cn/apk/xxx.apk` | `h5//apk/xxx.apk` | 404 报错里 `Key: h5%2F%2Fapk%2F...` |
  | `club.zhenhesheng.cn/download/` | **根目录** `/download/` | h5/download/ 已更新为 278, 但该路径仍返回 221 |
  → 即 `/apk/` 走 **h5/ 前缀**, `/download/` 走 **根目录**, 两者不一致。
  **结论: 发布下载页与 APK 时, `/h5/apk`+`/h5/download` 和 `/apk`+`/download` 两处都要传**,
  只传一处会导致自定义域名下"页面是新的但下载 404"或反之
- **修复动作**:
  1. 下载页版本 1.11.221 → **1.11.278**; 链接域名
     `cloud1-...tcloudbaseapp.com` → **`https://club.zhenhesheng.cn`**(2 处)
  2. APK 与下载页复制到 `dist/build/h5/apk/`、`dist/build/h5/download/`
  3. 三次上传: `dist/build/h5 → /h5/`(84 文件)、`h5/download → /download/`、`h5/apk → /apk/`
     ⚠️ **严格限定 cloudPath 到 /download/ 和 /apk/, 绝不传根路径**(铁律: 根 = 官网)
- **验证结果**:
  | 项 | 结果 |
  |---|---|
  | `club.zhenhesheng.cn/download/` | 200, 指向 278 + 自定义域名 ✅ |
  | `club.zhenhesheng.cn/apk/daoyuan-v1.11.278.apk` | 200, APK 魔数 PK 正确 ✅ |
  | 测试域名同路径 | 200 ✅ |
  | 官网首页(根) | 仍是「真和盛 \| 道家文化传承」未被覆盖 ✅ |
  | H5 应用 /h5/ | v1.11.278 正常 ✅ |
- **未改动**: `src/utils/static-url.js` 的静态资源域名仍是测试域名 —— 那是图片请求,
  不会触发该 HTML 警告页; 且改了需验证 `club.zhenhesheng.cn/static/*` 是否落到 h5/, 暂不动
- **版本**: v1.11.278 (与 H5/小程序一致, APK 用当前已同步版本号构建, 未单独升版)

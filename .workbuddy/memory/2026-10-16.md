## 抖音端手机号一键登录 (commit 547093a, v2.0.4)
- **用户报障**: 抖音小程序登录页"手机号快捷登录"不弹手机号授权面板。
- **根因**: 该按钮只在 `#ifdef MP-WEIXIN` 下渲染, 抖音命中 `#ifndef MP-WEIXIN` 分支,
  拿到的是 H5/App 的"弹窗手动输入手机号+密码"方案 —— 从来就没有授权按钮。
- **修复**: 加 `#ifdef MP-TOUTIAO` 分支渲染 `<button open-type="getPhoneNumber">`;
  onLoad 最前面静默 `tt.login`(抖音规范: 用 getPhoneNumber 前必须先 tt.login,
  且**不能在授权回调里调** —— 会刷新登录态致 session_key 与加密时不匹配);
  按钮文案按平台规范改"手机号一键登录"(禁用诱导文案)。
- **抖音与微信的手机号授权是两套体系**(关键认知):
  - 微信: 回调 code → 后端 `api.weixin.qq.com/wxa/business/getuserphonenumber`(access_token)
  - 抖音新版(基础库≥3.51.0): 回调 code → 后端 `developer.douyin.com/api/apps/v1/get_phonenumber_info/`
    (header `access-token: <client_token>`, body {code}) → 返回 RSA 密文 → 应用私钥解密
    → `{purePhoneNumber, phoneNumber, countryCode, watermark}`
  - 抖音旧版: 回调 encryptedData+iv → session_key AES 解密(本项目未实现, 前端已优先走新版)
- **抖音 client_token 获取**: POST `https://open.douyin.com/oauth/client_token/`,
  body {appid, secret, grant_type:'client_credential'} → `data.access_token`
- **平台侧前置条件(代码无法代做, 已写进 config.local.example.js)**:
  1. 抖音开放平台 → 开发配置 → 配「应用公私钥」, **未配则 code 返回空字符串**(最常踩)
  2. 企业主体 + 「获取手机号」能力审核通过
  3. config.local.js 填 DY_CLIENT_SECRET + DY_APP_PRIVATE_KEY
- **后端新增**: `user.douyinPhoneLogin` 路由 + `getDouyinClientToken()`(缓存100min)
  + `rsaDecryptBase64()`(RSA-PKCS1-PADDING); 账号逻辑复用 phoneLogin 同一套;
  抖音账号记 `platform:'mp-toutiao'`

## 抖音端接入担保支付收银台 (commit c75e9b7, v2.0.5)
- **用户需求**: 抖音小程序支付界面把微信支付换成抖音平台担保支付, 由抖音收银台(前置组件)拉起
  微信/支付宝/抖音支付; 元宝支付保留; **微信小程序和 H5 支付界面保持不变**。
- **前端(仅 MP-TOUTIAO 分支)**: checkout.vue + order/detail.vue 的支付选项 wechat→douyin,
  默认选中 douyin, 元宝支付保留; 封装 `ttRequestPay()` 统一处理 tt.pay。
- **tt.pay 与微信支付的回调语义完全不同(关键认知)**:
  - `tt.pay({ orderInfo:{order_id, order_token}, service:5 })`
  - success 的 `code` 是数字: 0=成功 1=超时 2=失败 3=关闭 4=取消 **9=需商户自行查单**
  - fail 的 `errMsg` 是**字符串**错误码: 10000=支付失败 10001=调起微信失败 10002=微信未安装
- **后端(抖音担保支付 ecpay)**:
  - 预下单 `POST https://developer.toutiao.com/api/apps/ecpay/v1/create_order`,
    body {app_id, out_order_no, total_amount(**单位:分**), subject, body, valid_time, sign, notify_url, cp_extra}
    返回 `{err_no:0, data:{order_id, order_token}}`
  - 查单 `/query_order`; 回调 body {type, timestamp, nonce, msg, msg_signature}
  - **签名算法**: 除 sign/app_id/thirdparty_id/prod_id 外的参数**值**(不含key) trim 后,
    与「支付 **SALT**」(不是AppSecret!)一起**字典序排序**, & 连接, **MD5** hex
  - **回调验签**: `[token, timestamp, nonce, msg].sort().join('')` → **SHA1** hex, 与 msg_signature 比;
    成功后必须回 `{err_no:0, err_tips:'success'}`, 否则平台重试
  - 入口 HTTP 网关分支内置抖音回调识别(有 msg_signature/timestamp/nonce/msg 即进回调), 不占 action 命名空间
- **平台侧前置条件(代码无法代做, 已写进 config.local.example.js)**:
  1. 企业主体 + 「小程序担保支付」能力申请通过
  2. 后台勾选支付方式(微信H5/支付宝APP/抖音支付); **微信渠道还需微信商户管理员扫码签约**
  3. 拿 **SALT** 填 DY_PAY_SALT; 回调地址填 DY_PAY_NOTIFY_URL(不填抖音拒预下单, err_no 2003);
     回调验签 token 填 DY_PAY_CALLBACK_TOKEN
  4. iOS 虚拟物品不支持支付宝/微信, 仅安卓可用
- **未配置时**: 后端返回明确中文提示, 不静默失败。
- **验证**: 三端构建通过; 抖音产物含 key:"douyin" + tt.pay( + service:5 + orderInfo;
  微信端产物无 douyin、无 tt.pay, 订单详情仍"微信支付"(未污染); H5 未受影响。
- **grep 产物的坑**: minify 后 `key:"wechat",name:"微信支付"` 的字段顺序/引号会变,
  用 `key:"[a-z]*"` 单独抓 key 更可靠; 文本类(支付方式名)在 JS 里而非 ttml, 因为模板是数据驱动 `{{p.d}}`。

## 邀请链接改为 H5 注册页 (22:17, v1.11.319)
- **用户反馈**: 小程序上「复制邀请链接」不生效; 要求链接打开**直接到 H5 注册页并自动填好邀请码, 不用下载 App**
- **两个根因**:
  1. `inviteLink` 指向**下载页** `club.zhenhesheng.cn/download/?invite=xxx` → 好友打开被引导下载 App(正是用户不要的)
  2. v1.11.318 我用条件编译把小程序端的「复制邀请链接」换成了「复制邀请码」→ 小程序上根本没有复制链接入口, 所以"不生效"
- **改动**:
  1. `inviteLink` 改为 H5 注册页: `https://club.zhenhesheng.cn/h5/#/pages-sub/login/login?invite=${encodeURIComponent(daoCode)}`
     —— H5 是 **hash 路由**(`src/manifest.json` h5.router.mode=hash) 且部署在 `/h5/` 子目录, 故必须用 `/h5/#/页面路径?参数` 格式; 登录页 path=`/pages-sub/login/login`(pages.json 分包)
  2. 小程序端恢复「复制邀请链接」(次按钮), 主按钮仍是 `open-type="share"` 分享给好友; H5/App 端复制链接为主按钮
  3. 删除 `copyInviteCode` 及其按钮(链接已带邀请码且自动填充, 功能冗余)
  4. 文案改为"好友通过你的分享卡片或专属链接注册，自动填入邀请码，双方得 8 折优惠券"
  5. **登录页参数兜底** (`login.vue` onLoad): 除 `options.invite` 外, `#ifdef H5` 时再用正则从 `window.location.href` 解析一次, 兼容 `/h5/#/path?invite=X` 与 `/h5/?invite=X#/path` 两种写法, 防止外部链接打开时参数丢失导致邀请码没填上
- **验证**: H5 + mp-weixin 双端构建通过; 小程序产物确认含 `open-type="share"`、新链接 `h5/#/pages-sub/login/login?invite=`、且**旧 download 链接已不存在**; curl 校验线上 `version.DuaBZsP-.js` = **1.11.319** ✅; `curl https://club.zhenhesheng.cn/h5/` 返回 HTTP 200 + 标题「道元易学」
- **版本**: bump→v1.11.319, commit 3df0640, tag v1.11.319 -f; GitHub 已推送

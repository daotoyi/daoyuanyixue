## 微信物流助手双通道接入 (v1.12.4)
- **背景**: 用户问"微信小店发货免月结、现结、还便宜是怎么实现的", 要我给方案再决定
- **关键调研结论**:
  1. 微信「物流助手」是官方免费接口, 统一对接多家快递; 支持两种模式: 签约月结(绑网点账号) / **散单现付**
  2. **现付只支持顺丰 SF_CASH、德邦 DB_CASH 两家** —— 根因是**经营模式**: 直营制(顺丰/德邦/京东/EMS)总部统一结算, 微信对总部签一次即可全国通用; 加盟制(中通/圆通/韵达/申通)各网点老板独立核算, 无法跨网点统一代收, 故必须线下跟网点签约月结
  3. **纠偏: 现付 ≠ 便宜**。散单现付是标准零售价, 通常**贵于**月结协议价; 微信小店便宜的真正来源是腾讯集采的协议价, 不是因为现付
  4. `add_source`: 0=小程序订单(发物流服务通知) / **2=App或H5订单**(不发通知, 需 wx_appid) —— 比文档说的"仅支持小程序订单"宽松
  5. 顺丰下单 **`expect_time` 必传**(Unix秒; 0=已事先约定取件时间)
  6. 微信要求省份城市**带行政后缀**("广东省"/"广州市"/"天河区")
- **最重要发现**: 快递鸟的**轨迹订阅(1008)与即时查询(1002)本就不需要月结账号**, 只有在线下单(1001)需要!
  → 因此最优组合: **微信负责下单(现付免签约) + 快递鸟负责轨迹(已跑通, 不需月结)**, 避免重复实现轨迹逻辑
- **查生产数据库的方法(可复用技巧)**:
  - mcporter `callCloudApi action=DatabaseQuery` **不存在**(tcb 无此 action, 不要猜)
  - 可行做法:**建临时云函数**(云函数内 db 有完整 admin 权限) → `manageFunctions action=invokeFunction` 调用 → 用完删除
  - `createFunction` 的 func 参数用 **`name`**(不是 functionName); 且代码目录必须是 `functionRootPath/<函数名>/` (否则报"路径不存在")
  - 运行时用 **`Nodejs16.13`**(写 Nodejs16 会报不支持)
  - `deleteFunction` 必须显式传 **`confirm=true`**
  - fish shell **不支持 heredoc**, 写文件用 Write 工具
- **真实订单数据**(2026-09-05 查得): 总订单 70 单; 实体商品(product) 28 单; **已发货仅 2 单**(顺丰1/极兔1); 待发货 7 单
  - **订单表无任何来源端字段**(无 platform/source/client) → 无法从数据判断订单来自小程序/H5/App, 这是个待补的信息缺口
- **用户决策**: 订单主要来自**小程序** → 接微信物流助手, **保留现有快递鸟月结设计**(双通道)
- **实现** (v1.12.4):
  - 云函数 `adminLogisticsWxCreateOrder` + 路由 `admin.logistics.wxCreateOrder`(已加 STAFF_ROUTES)
  - 复用已有 `getWxAccessToken()`(config.local 的 WX_APPSECRET 已配置, 长度32, 无需额外配置凭证)
  - `openid` 从 `users` 表按 uid 取(微信物流通知要用); 无 openid 仍可下单, 只是不推通知, 会在结果里提示
  - 下单成功后: 回填订单运单号 → 存 waybill_data 到物流表 → 发消息 → **调 kdniaoSubscribe 订阅轨迹**
  - 前端发货页: 在线下单模式下再分通道「微信现付 / 快递鸟月结」, 默认微信; 月结账号选择仅快递鸟通道显示

## 订单 platform 来源端标记 (12:00, v1.12.5)
- **需求**: 加 platform 标记订单来源(此前查数据发现订单表无任何来源端字段, 无法判断小程序/H5/App)
- **实现要点**: 在 `src/api/api.js` **统一注入**, 业务页面无需各传 —— 新增 `platformTag()`:
  - 优先运行时 `uni.getSystemInfoSync().uniPlatform` → app / **web** / mp-weixin; `web` 统一转成 `h5`
  - 兜底用条件编译(MP-WEIXIN/H5/APP-PLUS)返回对应常量, 再兜底 'unknown'
- **注入点(4 个下单入口全覆盖)**: `createOrder`(order.create) / `unlockTool`(tool.unlock) / `pandaoBook`(pandao.book) / `rechargeCreate`(recharge.create)
- **云函数**: 5 处 `db.collection('orders').add()` 全部加 `platform: String(data.platform||'').trim() || 'unknown'`
  —— 订单创建点分散在 createOrder(1949) / rechargeCreate(1929) / toolUnlock 余额分支(1999) / 预约(2934) 等, **改动前先 grep `collection('orders').add(` 全列出来**, 否则会漏
- **后台可见**: dashboard 订单列表状态列下加彩色标签(小程序绿/H5蓝/App橙); `PF_TEXT`/`PF_CLS` 映射; **老订单 platform=unknown 时不显示标签**(不干扰)
- **验证技巧**: 小程序产物里 platformTag 被打包进 `common/vendor.js`(不在 app.js); 框架自带的 `uniPlatform:"mp-weixin"` 可佐证运行时取值正确
- **版本**: bump→v1.12.5, commit 65d8fc8, tag v1.12.5 -f; H5+小程序构建通过; 云函数已部署; curl 校验线上 `version.BVMzwd7P.js` = **1.12.5** ✅; GitHub 已推送
- **后续可做的延伸**: 有了 platform 后可让发货页**自动推荐通道**(小程序订单→微信现付, 其余→快递鸟), 不必每次手选

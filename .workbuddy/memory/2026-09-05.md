## 微信物流助手双通道接入 (v1.12.4)
- **背景**: 用户问"微信小店发货免月结、现结、还便宜是怎么实现的", 要我给方案再决定
- **关键调研结论**:
  1. 微信「物流助手」是官方免费接口, 统一对接多家快递; 支持两种模式: 签约月结(绑网点账号) / **散单现付**
  2. **现付只支持顺丰 SF_CASH、德邦 DB_CASH 两家**(2026-09-05 官方文档复核确认, 与代码 WX_CASH_CODES=['SF','DB'] 一致)
  - **⚠️ 勘误(2026-09-05 用户追问后复核)**: 此前写的"直营制(顺丰/德邦/京东/EMS)总部统一结算→现付"是**过度泛化, 错误**。真实情况: 京东 JDL、EMS 虽也是直营, 但**不在现付清单**, 仍需线下签约绑定账号; 微信实际只给 SF、DB 开了现付通道, 与"是否直营"无简单对应。正确业务规则: **现付 = 仅 SF_CASH + DB_CASH, 其余一律走签约月结(快递鸟通道)**
  - 旧文档/教程里出现的 `OTP_CASH`(承诺达特快)、`PJ_CASH`(品骏快递) 是**过时残留** —— 承诺达已被顺丰出售/关停、品骏 2020 年唯品会已关停(业务转顺丰), 这两个 BizID 现已不可用, 切勿加入
  3. **纠偏: 现付 ≠ 便宜**。散单现付是标准零售价, 通常**贵于**月结协议价; 微信小店便宜的真正来源是腾讯集采的协议价, 不是因为现付
  4. `add_source`: 0=小程序订单(发物流服务通知) / **2=App或H5订单**(不发通知, 需 wx_appid) —— 比文档说的"仅支持小程序订单"宽松
  5. 顺丰下单 **`expect_time` 必传**(Unix秒; 0=已事先约定取件时间)
  6. 微信要求省份城市**带行政后缀**("广东省"/"广州市"/"天河区")
- **最重要发现**: 快递鸟的**轨迹订阅(1008)与即时查询(1002)本就不需要月结账号**, 只有在线下单(1001)需要!
  → 因此最优组合: **微信负责下单(现付免签约) + 快递鸟负责轨迹(已跑通, 不需月结)**, 避免重复实现轨迹逻辑
- **查生产数据库的方法(可复用技巧)**:

  - 可行做法:**建临时云函数**(云函数内 db 有完整 admin 权限) → `manageFunctions action=invokeFunction` 调用 → 用完删除
  - `createFunction` 的 func 参数用 **`name`**(不是 functionName); 且代码目录必须是 `functionRootPath/<函数名>/` (否则报"路径不存在")

## 修复: 微信面单误存 print_template 打出乱码 (12:21, v1.12.7)
- **发现契机**: 用户问"微信物流助手和快递鸟有什么区别", 我核对代码时顺带发现此 bug
- **Bug**: 微信下单返回的 `waybill_data` 是**键值对数组**(非 HTML), 我却 `savePrintTemplate(..., JSON.stringify(waybill_data))` 存进了 `print_template` 字段
  - 后果链: 下次进该订单发货页 → onLoad 探测 `adminLogisticsPrintTemplate` 见 print_template 有值 → `hasTemplate=true` → **显示「打印面单」按钮** → 点击 `doPrint(JSON字符串)` → iframe 写 JSON → **打印出乱码**
  - 当下单页即时返回时 `print_template:''` 所以当场不显示按钮, 但**二次进入就会中招** —— 属于延迟暴露型 bug
- **修复**:
  1. 微信通道改存**独立字段 `waybill_data`**, 不再污染 `print_template`(两处都改, 新增记录与更新记录)
  2. `doPrint(html)` 加**格式防线**: 内容非空且首字符不是 `<` 视为非 HTML, 弹窗提示改用「微信打单 PC 软件」或让快递员上门打单, 不再盲目打印
- **教训**: 两个来源的"面单"**数据结构不同**(快递鸟=HTML字符串, 微信=键值对数组), 复用同一个存储字段前必须先确认格式; 打印这类"输出即不可逆"的操作应加输入校验

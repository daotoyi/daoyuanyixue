## v1.11.154: 后台越权漏洞修复 + 订单分析环形图单色修复

### 问题1: 齐静春(ZHS00001)账户有管理员权限 (严重安全漏洞)
- **根因**: 云函数 `requireAdmin` / `requireStaffAllowed` 完全信任客户端传的 `opRole`/`role` 字段:
  `if (role === 'admin' || role === 'manager') return true` → 任何用户带 `opRole:"admin"` 即可越权访问后台
  (实测 uid=4 role=user 的齐静春伪造 opRole 拿到全量后台数据/用户列表)
- **DB 实况**: 齐静春数据库角色确实是 `user`(uid=4, 13800138001/123456 测试账号), 非管理员
- **修复**: 新增 `dbUserRole(data)` helper (按 opUid/uid/user_id 查数据库真实角色), 全部权限判断以 DB 为准:
  1. requireAdmin / requireStaffAllowed → 一律查 DB
  2. publishMoment 发布权限 → 查 DB
  3. register 公开注册 → 强制 role='user' (原来接受 data.role 可注册即管理员)
  4. adminUserUpdate / adminUserDelete 的 opRole 兜底 → 删除, 只查 DB
- **验证**: 齐静春伪造 opRole=admin → 403; 超管 uid=1 → 200; 云函数热实例缓存约 30-60s 后生效

### 问题2: 订单分析环形图只有商品一种颜色
- **根因**: 后端 adminOrderAnalysis 的 typeMap 固定返回全部3类(product/course/tool_unlock),
  课程/AI解盘 count=amount=0 时前端 legend 仍显示3种颜色, 但环形图 seg=0 不可见 → 只剩商品色
- **修复**: 后端过滤 `count>0 || amount>0` 才返回 → pieData 只含实际成交类型, 图例与环形图一致
- **验证**: 线上 pieData 现只返回 `[{key:product, count:6, amount:1268.06}]`

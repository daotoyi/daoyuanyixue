## 快递鸟物流查询接入 (v1.12.0, minor 版本)
- **用户需求**: 接入快递鸟发货物流, 发货后**自动回调同步物流信息**, 用户可查看物流; 版本升级为 **1.12.0**
- **架构**: 订阅(推送)为主 + 即时查询兜底
  1. 后台发货 → 调快递鸟「轨迹订阅」接口(RequestType=**1008**) → 快递鸟在轨迹变化时 POST 回调我们
  2. 回调 → 落库到 `logistics` 集合 → 用户端直接读本地轨迹(快, 不依赖实时请求)
  3. 用户查看时若本地无轨迹 → 调「即时查询」(RequestType=**1002**) 兜底补全
- **云函数** (`cloudfunctions/dy-api/index.js`, 插在 `LOGISTICS_COMPANIES` 之后):
  - `kdniaoSign(requestData, appKey)` = `encodeURIComponent( base64( md5(RequestData + AppKey) ) )`
  - `kdniaoFormPost()` —— 专用 form-urlencoded POST(不能复用 `httpGetJson`, 那个是 JSON+Bearer)
  - `getKdniaoConfig()` —— 读 `settings` 集合 group=**logistics**
  - `parseFormBody()` —— 快递鸟回调是**表单 POST 非 JSON**, 必须自己解析
  - `kdniaoSubscribe()/kdniaoQuery()/saveLogisticsTrack()`
  - 路由: `kdniao.callback`(HTTP 回调) / `order.logistics`(查轨迹) / `admin.logistics.subscribe`(后台重订阅)
  - `adminOrderShip` 内 `reportShippingInfo` **之后**追加 `kdniaoSubscribe`
  - 签收(State=3) 回调里自动把「待收货」订单置为「已完成」

## 多月结账号管理 + 多仓库 (21:32, v1.12.3)
- **用户决策**: ①只做多账号(不做比价选快递) ②**要含多仓库**(每账号独立发件地址) ③暂不需要自动比价
- **背景**: 不同快递公司月结号完全不同(顺丰强制 CustomerName+CustomerPwd, 京东要商家编码), 单组 `customer_name` 撑不住多快递
- **数据结构**: settings group='logistics' 增 `accounts` 数组, 每条 `{id,label,shipper_code,customer_name,customer_pwd,pay_type,enabled,is_default,sender{...}}`
  - `shipper_code` 为空 = 通用账号(不限快递公司)
  - `sender` 留空则回落全局发件人(单仓场景不用填)
- **匹配优先级** (云函数 `matchAccounts`): ① 精确绑定该公司的已启用账号 ② 通用账号 ③ 旧配置合成的默认账号
  - 命中1个 → 自动用; 命中多个 → 取 `is_default` 那个, 没有则要求前端传 `account_id`; 未命中 → 回落全局发件人(可能现付)
- **云函数**: 扩展 `getKdniaoConfig()` 返回 accounts(兼容旧顶层单账号→自动合成一条 legacy); 新增 `accountEnabled/accountSender/matchAccounts/adminLogisticsAccounts`; 路由 `admin.logistics.accounts`(已加 STAFF_ROUTES)
- **后台设置** (`dashboard.vue`): 新增「月结账号」区块(**数组不走 settingsForm 的扁平字段循环**, 单独用 `logisticsAccounts` 维护)
  - `loadSettings` 里单独加载 accounts; `saveSettings` 里 `configs.accounts = logisticsAccounts.value` **必须并入**, 否则删除不生效(服务端会保留旧值)
  - 账号 CRUD: 备注名/绑定快递公司/月结号/月结密码/支付方式/发件仓(省市区县详细)/启用停用/设为默认
- **发货页** (`logistics.vue`): `watch(company)` → 自动拉该公司的账号; 1个直接显示"将使用 X", 多个给卡片选择(显示仓库名); 下单传 `account_id`
- **坑**: 新增 API 后**忘了在 `src/api/api.js` 导出** `adminLogisticsAccounts` → 构建失败; 加云函数路由时务必同步补前台导出

## v1.11.236: 课程视频支持 4GB+ 大文件 (COS Multipart Upload 分片上传)
- 需求：课程视频超 4G 无法上传成功；用户明确: 单文件>5GB 自动分块上传
- 根因：H5 直传 COS 单次 PUT/POST 上限 5GB, 4GB 附近已不稳定; 且原 uploadFile 对非图片会先整文件读内存转 base64 再直传(4G 视频直接爆内存)
- 方案: COS Multipart Upload, 云函数签发分片预签名 URL, 前端 fetch 直传分片
- 云函数 dy-api 新增 4 接口 (路由 storage.*):
  - createMultipart: cos.multipartInit → uploadId (ContentType=video/mp4)
  - partUploadAuth: cos.getObjectUrl(Method:PUT, Query:{partNumber,uploadId}, Expires:600) → 预签名URL (含 x-cos-security-token 参数, 前端直接 PUT 无需 header)
  - completeMultipart: parts 缺省时 cos.multipartListPart 服务端查已传分片 ETag (规避浏览器 CORS 读不到 ETag 头) → multipartComplete → 返回 fileID
  - abortMultipart: 失败清理
- ⚠️ SDK 坑: multipartListPart 返回字段是 **Part** 不是 Parts; PartNumber 是字符串 "1" 需 Number() 转换后与前端数字数组匹配, 否则"未找到已上传的分片"
- 依赖: package.json 新增 cos-nodejs-sdk-v5 (平台部署自动安装, 已验证)
- 密钥: 云函数运行时 TENCENTCLOUD_SECRETID/SECRETKEY/SESSIONTOKEN (自动注入, 权限=本环境 COS), getCos() 懒加载
- 前端 src/api/cloudbase.js:
  - MULTIPART_THRESHOLD=3GB (>3GB 走分片, 覆盖用户实测 4G 失败场景; COS 硬限 5GB), PART_SIZE=64MB, 并发 3
  - 关键修复: 大文件判断提前到 base64 读取之前 (!isImage 时先 probeFileSize), 且非图片不再走 base64 读取(白读内存); 否则 4G 视频在读 base64 时就崩了
  - probeFileSize(H5 blob.size / App getFileInfo), readBlobSlice(H5 Blob.slice / App readFile position+length)
  - uploadFile 增加 onProgress 参数 (dashboard 上传视频时 showLoading 显示百分比, 2% 步进)
- 验证: 全链路测试通过 (create → 2 分片 PUT → complete → fileID 返回); 测试文件已清理 (manageStorage action=delete force=true)
- 版本 v1.11.236 (commit a0440d3 + 5eaa02e) H5 已部署 + 云函数已部署 + 小程序已构建; 推送仍被 GitHub 拦截

## 盘道茶话会「过期自动顺延 + 旧预约归档」(v1.12.31 → 修复 v1.12.32)

### 需求
盘道场次（如【盘道茶话会】）若本周时间已过，自动更新到下一个同周几同时间的 occurrence；顺延后已预约信息"重新计算"——按用户选择为**旧预约归档(标记`已结束`)、新周从零报名**（非保留席位顺延）。

### 实现 (cloudfunctions/dy-api/index.js)
- `rollForwardPandaoSession(session)`：若当前 occurrence 已结束，把 `start_date` 推进到 `pandaoNextOccurrenceDate(day,time)`（同周几、结束时刻严格 > 现在），并归档该场次有效预约订单（status∈待付款/已完成/待发货/待收货 → `已结束`，留 archived_at/refund_reason）。
- `pandaoNextOccurrenceDate`：从今天起14天内找第一个匹配周几且结束时刻>now的日期。
- `pandaoList` / `pandaoDetail` / `pandaoMine`（adminCourseList 路径）读取时自动对每条会话调 `rollForwardPandaoSession`，前端展示(日期/临近提醒/我的预约)全部从 `start_date` 派生，无需改前端。
- `pandaoBookers` 排除 `已结束`（同已有的 已取消/已退款），旧预约自然退出头像墙与"我的预约"。

### 🔴 关键 Bug（已修 v1.12.32）
- `pandaoWeekdayNum` 原正则 `/周[日一二三四五六]/` 只匹配"**周**六"格式，但 DB 里 `day` 字段存的是"**星期**六"（星+期+六），匹配失败返回 null → `pandaoNextOccurrenceDate` 返回 null → `rollForward` 直接 `return false`，**所有场次都不顺延**（线上实测 id=5/6 仍显示旧日期）。
- 修复：改为 `String(day).match(/[日一二三四五六]/)` 取最后一个中文字，map 用单字 `{日:0,...,六:6}`，兼容"周六"/"星期六"两种写法。本地 node 复现确认修复后 `wd(星期六)=6`、`next(周六14:00)=2026-09-12`。
- v1.12.32 仅改云函数 `dy-api/index.js`（1行正则+map），前端无需改动；版本号四端仍同步（bump 到 v1.12.32）。

## 盘道场次「固定成员(盘道班底)」配置 + 详情页头像墙 (v1.12.33)

### 需求
后台盘道管理增加"固定出库盘道活动人员"板块：后台添加后，每个盘道活动（场次）详情页均显示相应人员头像。
经澄清确认两点设计：① 每场次独立配置（不同场次显示不同人员，存每场次 `fixed_members` 字段，非全局统一名单）；② 成员从 App 已注册用户搜索选择（按昵称/手机/道号搜，自动带出头像昵称），非手动填姓名+链接。

### 实现
**后端 cloudfunctions/dy-api/index.js**
- 新增 `adminUserSearch(data)`：按 `keyword` 对 `users` 集合 `nickname/phone/dao_code` 三字段模糊匹配（正则内联转义 `kw.replace(/[.*+?^${}()|[\]\\]/g,'\\$&')`，因全局无 `escapeRegExp`），手机脱敏 `(\d{3})\d{4}(\d{4})`→`$1****$2`，过滤 `status==='deleted'`，limit 20；返回 `{uid,nickname,avatar,phone}`。
- `adminUserSearch` 注册进 `ROUTES`（admin.users.delete 之后）+ 加 `VIEWER_ROUTES`（只读允许 manager/viewer 调，实际仅超管/管理员能进编辑）。
- `adminPandaoCreate`/`adminPandaoUpdate` 的 `doc` 增 `fixed_members`：数组，每元素 `{uid,name,avatar}`（uid→Number、name≤30字、avatar≤500字），Create 上限 30 且 `Array.isArray` 守卫；Update 仅 `data.fixed_members!==undefined` 时更新（不覆盖旧值）。

**前端**
- `src/api/api.js`：导出 `adminUserSearch = _admin('admin.users.search')`（紧跟 adminUserDelete）。
- `src/pages-sub/admin/dashboard.vue`：盘道编辑表单加"固定成员"区——已选 chips(头像+昵称+×) + 搜索框(防抖 300ms 调 `adminUserSearch`，过滤已选，`resolveCloudUrl` 解析头像) + 候选下拉点选；`emptyPdForm()` 加 `fixed_members:[]`；`editPandaoSession` 改 async 回显时复制并解析 `_avatar`；`addPandaoSession` 的 create/update 调用均传 `fixed_members`。
- `src/pages-sub/pandao/detail.vue`：onLoad 读 `session.fixed_members`，`Promise.all` 对 `m.avatar` 调 `resolveCloudUrl` 存 `_avatarUrl`，`fixedMembers` 复用 `MAX_BOOKER_AVATARS=10` 折叠为 +N；模板在"已预约"墙前插"盘道固定成员 N 人"墙，复用 `.pd-bookers` 样式，`openUserProfile(m)` 进主页。

### 关键细节 / 取舍
- `fixed_members` 存**快照**{uid,name,avatar}，用户改头像后详情页可能略旧（避免每次拉全量查询，可接受）。
- 与现有 `homePandaoFixed`/`pandaoBanners`（settings 组）解耦：固定成员是每场次属性，故存文档而非 settings。

## 盘道时间未与后台同步修复 (v1.12.35)

### 现象
后台手动改盘道场次日期/时间后, 前端详情页与首页卡片显示的时间与后台设置对不上(被自动拉回本周规律日)。

### 根因
`rollForwardPandaoSession` 每次 `pandaoList`/`pandaoDetail` 读取时, 都 `pandaoNextOccurrenceDate(day,time)` 按周几+时间重算下一周日期并**无条件覆盖 `start_date`**。后台手动设的具体日期(哪怕还在未来、场次未结束)会被拉回本周规律日 → 前端不同步。

### 修复 (cloudfunctions/dy-api/index.js, 3058 起)
- 顺延前先判 `start_date` 的结束时刻 `occEnd = new Date(y,m-1,d,end.h,end.m)` 是否 `> Date.now()`: **未结束 → 直接 return false 保留手动设置, 不回拉**; 已结束才 `pandaoNextOccurrenceDate(day,time)` 推进到下一周。
- 保留「自动延期下周」能力(规律场次过期后照常顺延), 同时尊重后台手动设的未来日期。
- **成员不受影响**: `fixed_members` 顺延时只 `update({start_date})` 不动; 编辑接口仅 `data.fixed_members!==undefined` 才改。手动改期/自动顺延, 固定成员均保持不变(用户要求)。

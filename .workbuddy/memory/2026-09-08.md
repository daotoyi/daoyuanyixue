# 2026-09-08 工作日志

## 订单详情「取消订单」不生效 — 真因定位与修复 (v1.12.17)
- **现象**: 列表页(订单管理)取消生效, 详情页取消不生效; v1.12.16 测仍无效。
- **前端**: v1.12.16 已修(取消后 `load()` 重新拉详情对齐列表页)并确认线上分包 chunk `pages-sub-order-detail.C62V2rug.js` 含修复标记 ✅ — 非前端问题。
- **真因**: `wxpay-v3.js` 的 `request` **无超时**, 已支付(待发货)订单取消走 `await wxpay.refund()` 时, 若微信接口在该云函数环境偶发慢/挂, 整段 `await` 永不返回 → 取消卡死 → 前端"点了没反应"。v1.12.16 只 catch 了**报错**没防**挂起**。
- **修复(双层)**:
  1. `wxpay-v3.js` `request` 加 `timeout:8000` + `req.on('timeout', ()=>req.destroy(new Error('微信接口请求超时')))` — 所有微信调用不再挂死。
  2. `dy-api/index.js` `cancelOrder` 把退款逻辑用 `Promise.race([refundP, timeout(5000)])` 包裹 — 退款即使挂起, 订单也必在 ~5s 内取消(标记 `refund_failed` 留后台)。
- 部署: dy-api 已更新; H5 重建重传 `/h5/` (83 文件); 版本 `v1.12.17 (b5b20f2)`, main+tag 已推送。
- **经验**: 云函数内任何外部 HTTP 调用(微信/腾讯云/COS)都必须加超时, 否则会随机卡死整个请求。

## 上传队列"只生效最后两个" (00:33)
- **现象**: 课程视频排队较多时, 只有最后两个上传真正生效(写回课程), 前面排队的视频丢失; 队列顺序显示正常
- **根因**: `openCourseForm`(dashboard.vue ~3449) 每次打开/重开课程编辑弹窗都用 `epKey()` 给 episodes 生成**全新 _key** 重建数组; 若上传/排队途中重开弹窗, 队列里持有的 `ep` 对象引用脱离新数组 → 这些上传完成时把 video 写回已失效的旧对象(丢失), 只有重开后才入队的最后两个(活对象)才生效
- **修复(纯前端, 无需重部署云函数)**:
  1. `openCourseForm` 顶部加早返回: 同一课程(id 相同)且仍有 `currentUploadingEp`/`uploadQueue` 时, 直接 `showCourse=true` 复用内存表单, 不重建 episodes(防脱离); 切换不同课程仍走原清理逻辑
  2. `startUpload` 完成写回改为稳健命中: `liveEp = episodes.find(_key匹配) || episodes[indexOf(ep)] || ep`, 再 `liveEp.video=url`; 弹窗重建/课时重排也不丢视频
- **版本**: bump→v1.11.303, commit f6ef3e4, tag v1.11.303 -f; H5 构建 upload /h5/ 成功, 源站 `version.BCO4OMLH.js` 含 1.11.303 已 curl 校验 ✅; GitHub push 成功(d32e7e0..f6ef3e4 + 新 tag v1.11.303)
- **注**: 单弹窗会话(不重开)本就串行写回正常; 此 bug 触发条件是"上传/排队途中重开弹窗"。若用户未重开仍只生效最后两个, 需再排查单会话路径
